# Identity discovery vectors

Deterministic, signed protobuf responses generated by
`tests/identity_discovery.rs::should_export_nonunique_sdk_fixtures`:

```sh
cargo test -p drive-proof-verifier --test identity_discovery should_export_nonunique_sdk_fixtures -- --ignored
```

`pvN-{legacy,current}-{0,1,2}.bin` covers first match, next match, and exhaustion.
Each version answers in one format: PV12 and PV13 in the legacy format (field 2),
PV14 in the current format (field 4). The other combinations are signed but must be
refused; the generator checks both outcomes before writing. `newer-current-0.bin` is
a first match signed by protocol version 1000, far above any real version, so it is
read with the newest known rules whatever the latest version is.
`../document-outcome/newer-{request,response}.bin` is the same for a protocol 14
document outcome; it uses `pv14-contract.bin`.
The fixed test signing key is `[1; 32]`; `quorum-key.bin` is its public key.
`key-hash.bin` is the requested index key. These are synthetic fixtures, never
network trust anchors. The SDK tests replay these through the normal proof and
signature verifier.

`mainnet/` holds real answers from mainnet protocol 13 nodes in the legacy format,
recorded at height 456535 by
`rs-sdk/tests/identity_discovery_live.rs::should_capture_mainnet_legacy_nonunique_vectors`
(`DASH_SDK_CAPTURE_MAINNET_VECTORS=1 cargo test -p dash-sdk --test identity_discovery_live capture -- --ignored`):
`match-*` is a first match (`match-identity.bin` is the identity found) and
`absence-*` proves no identity after `[0xff; 32]`. Each `*-quorum-key.bin` is the
public key of the quorum that signed that answer, read from the trusted quorum
service at capture time. Responses are stored as the SDK re-encodes the decoded
message; the proofs inside are opaque byte fields and are kept verbatim.
`tests/identity_discovery/mainnet.rs` replays them offline.
