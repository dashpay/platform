# Protocol gate vectors

Deterministic, signed protobuf responses generated by
`rs-drive-abci/tests/protocol_gate.rs::should_export_protocol_gate_sdk_fixtures`:

```sh
DASH_SDK_EXPORT_PROTOCOL_GATE_VECTORS=1 cargo test -p drive-abci --test protocol_gate should_export_protocol_gate_sdk_fixtures -- --ignored
```

The SDK refuses a request that only newer nodes serve until a verified answer shows
the network runs a protocol version that serves it. When it does not know that yet, it
asks for the genesis epoch first. `rs-sdk`'s protocol gate tests replay these answers
through the normal proof and signature verifier:

- `epoch-probe-pv13.bin`, `epoch-probe-pv14.bin`: the genesis epoch
  (`GetEpochsInfoRequestV0 { start_epoch: Some(0), count: 1, ascending: true, prove: true }`)
  proved by a node at genesis state of protocol 13 or 14, signed at that version.
- `epoch-probe-newer.bin`: the same answer from a protocol 14 state, signed as protocol
  version 1000, far above any real version, so the SDK always reads it with the newest
  rules it knows.
- `contracts-by-range-pv13.bin`: a protocol 13 node's answer to
  `GetDataContractsByRangeRequestV0 { start: None, limit: Some(10), ids_only: true, prove: true }`,
  a request every node serves from protocol 14.
- `latest-versions-pv13.bin`: a protocol 13 node's answer (the multi-contract proof) to
  `GetDataContractsLatestVersionsRequestV0 { ids: [[0x42; 32]], include_contracts: false, prove: true }`.

Every answer carries metadata at height 10, Core chain-locked height 1, epoch 0, time
`1_700_000_000_000` and chain id `dash-testnet-51`. The fixed test signing key is
`[1; 32]`; `quorum-key.bin` is its public key (quorum type 106, quorum hash `[2; 32]`).
These are synthetic fixtures, never network trust anchors. The generator verifies every
answer before writing it, and `should_keep_the_recorded_protocol_gate_vectors_verifiable`
checks the committed files still verify.
