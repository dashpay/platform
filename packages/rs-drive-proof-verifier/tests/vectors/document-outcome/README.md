# Document-outcome vectors

Deterministic, signed `waitForStateTransitionResult` answers for a DPNS `preorder`
document create, generated by
`tests/document_outcome.rs::should_export_document_outcome_sdk_fixtures`:

```sh
cargo test -p drive-proof-verifier --test document_outcome should_export_document_outcome_sdk_fixtures -- --ignored
```

`pvN-{request,response}.bin` is the broadcast request and the proved answer of a
protocol N producer, and `pvN-contract.bin` is the contract the SDK tests load.
Protocol 13 proves the document alone; protocol 14 also proves the owner's credit
balance. `newer-{request,response}.bin` is the protocol 14 answer signed as protocol
version 1000, far above any real version, so it is read with the newest known rules
whatever the latest version is; it uses `pv14-contract.bin`.

`pv14-documents-response.bin` is a `getDocuments` answer for all `preorder` documents of
`pv14-contract.bin`, limit 10, over a state holding one document, signed at protocol 14 at
height 10, generated by
`tests/document_query_signature.rs::should_export_document_answer_sdk_fixture`:

```sh
cargo test -p drive-proof-verifier --test document_query_signature should_export_document_answer_sdk_fixture -- --ignored
```

The fixed test signing key is `[1; 32]`; `quorum-key.bin` is its public key. These
are synthetic fixtures, never network trust anchors. The SDK tests in
`rs-sdk/src/sdk/signed_version_tests.rs` replay them through the normal proof and
signature verifier.
